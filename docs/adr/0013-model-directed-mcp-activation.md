# 由模型按需建立 MCP 连接

2026-11-13 已确认的设计方向：已启用的 MCP 服务供模型按任务需要选择，不再因为 Agent 开始执行就自动连接所有服务。模型先获得轻量的服务目录，选择服务后才建立连接并发现工具；浏览器任务不应仅因全局启用了 Jira 就启动 Jira 进程并加载其工具定义。这沿用 [ADR 0005](0005-local-execution-and-model-decisions.md) 的模型负责相关性判断原则，接受需要服务的任务多一次选择步骤，以减少无关启动和上下文开销。

保留每个 Agent 独立拥有、复用并在结束或取消时清理自己的连接；后续消息对应新的 Root Agent，需要服务时重新连接。此次不共享跨 Agent 或 Chat 的客户端，接受必要的重复启动开销，保持现有取消、配置采用和清理归属。

已确认服务目录包含已启用服务的稳定 ID、名称及可选的简短说明，不为生成目录连接服务或提供凭据。说明由用户在 Settings 编辑；Jira 模板提供默认说明，已有服务缺少说明时按空值兼容，不要求用户补填。说明帮助模型判断名字含糊的服务用途，不由本地根据任务语义筛选服务。

模型选择服务后，复用现有 `mcp_startup({service_id})` 建立连接并完整发现工具；下一次模型请求获得该服务的全部工具定义，在该 Agent 内继续提供。此次按服务选择，不另加单工具检索或筛选机制。模型可以按任务需要选择多个服务；其他服务保持未启动，目录本身不证明连接成功或服务具有任何工具。

既有 Settings、Jev 安全审核、配置变更与禁用／删除检查、有界前置准备、失败诊断、不自动重放业务调用以及取消和清理规则继续适用。Root Agent 与 Sub-agent 遵循相同的按需连接规则；先前消息或其他 Agent 使用过某服务，不触发本 Agent 自动连接。已有连接仍按显式重连采用最新保存配置。

2026-11-13 用户已确认完整设计，实施规格见 [#222](https://github.com/tylerlong/weft/issues/222)，尚未实施。此决定取代 [ADR 0009](0009-mcp-client-integration.md) 的自动初始化及目录提供规则，保留其余约束；现有实现仍自动初始化所有已启用服务。实施时须同步更新用户指南、开发工具契约、任务指令及验收记录，明确区分已接受的设计、实际运行行为与历史验证证据。
